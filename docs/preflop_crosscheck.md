## Where the engine and the brief differ

The engine wins each of these. Checked at `Manchester-AI-Society/poker_bot_infrastructure` commit `8b89346`.

| Topic | Brief or docs | Engine or current repo | What we did |
|---|---|---|---|
| Format | Groups of 8 then a final | README and `event.json`: one round-robin. `arena/tournament.py` supports both | Designed for halves of ~100 hands, which holds either way |
| RNG in `__init__` | Create it there | `arena pack` pickles the built object, so its state would repeat every half | Kept it there and reseeded on the first `act` per process |
| Thinking budget | 0.2 s per deal per half | Also true, but the first decision's timer includes starting the process and unpickling | Tables stay small and load fast |
| Fold-to-open | Implied unobservable as BB | True for SB folds. As SB, a fold to our non-all-in raise can be inferred | Counted, with a fold to our all-in left uncounted |
| Hand number | Not mentioned | In the engine state, but `GameState` doesn't expose it, so SB folds stay invisible | SB rates use hands seen as the denominator, so they run high |
